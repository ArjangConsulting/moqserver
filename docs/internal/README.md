# Internal Planning Docs

These documents are **internal planning and design artifacts**, not user-facing
documentation. They capture historical scope decisions, the implementation
roadmap, and the original product spec.

They are kept in the repository for contributors but are intentionally separated
from the user-facing docs in `docs/`. Treat them as background context, not as a
source of truth for current behavior — when they disagree with the code or the
top-level `docs/`, the code and `docs/` win.

User-facing documentation lives in:

- `../../README.md` — quick start
- `../API_GUIDE.md`, `../ADMIN_API.md`, `../FORMAT_IMPLEMENTATION.md`, `../ERROR_CATALOG.md`
- `../../ARCHITECTURE.md`, `../STUDIO_ARCHITECTURE.md`
